# Sustainability through System Prompting

This repository contains the experimental code, materials, final data, LLM-judge outputs, and statistical analysis for the study.

**Preregistration (OSF):** https://osf.io/ajhrc/

## Setup Instructions

### Step 1: Install Dependencies

In the project root, create a Python virtual environment, activate it and install the required packages.

```bash
python -m venv venv
source ./venv/bin/activate
pip install -r ./requirements.txt
```

### Step 2: Ensure input data are present

The `data/` folder must be present. It contains the system prompts and user prompts required for the experiment. The script will fail if the input files are missing.

### Step 3: Adjust Experiment Parameters

In `exp.py` you can adjust the following parameters:

| Parameter                            | Description                                                                                          |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| `MODEL_LIST`                         | A list of Ollama model slugs to use.                                                                 |
| `USER_PROMPT_DIR`                    | Path to the user prompt source folder.                                                               |
| `USER_PROMPT_COUNT`                  | How many user prompts to use. Must be smaller or equal to the total no. of lines in the source file. |
| `GENERAL_SYSTEM_PROMPT_SRC_PATH`     | Path to the general case system prompt.                                                              |
| `SUSTAINABLE_SYSTEM_PROMPT_SRC_PATH` | Path to the sustainable case system prompt.                                                          |
| `HARDWARE_WARMUP_PERIOD_SECONDS`     | How long should the hardware warmup task be run before the experiment.                               |
| `IDLE_PERIOD_BETWEEN_RUNS_SECONDS`   | How much time to idle between each model run.                                                        |
| `OLLAMA_TOKEN_LIMIT`                 | Max token count for Ollama.                                                                          |
| `CODECARBON_LOG_LEVEL`               | CodeCarbon log level. Default is `error`.                                                            |

### Step 4: Pull models from Ollama

Pull the desired models before running the experiment or Ollama will return a not found error:

```bash
ollama pull <MODEL_SLUG>
```

To delete an installed model, use:

```bash
ollama rm <MODEL_SLUG>
```

### Step 5: Execute Script and Begin Experiment

Execute the main program `exp.py`:

```bash
python exp.py
```

You may be prompted to enter your system's password, as CodeCarbon needs to access the hardware information of the system.

### Step 6: Review Experiment Results

The `outputs/` folder will be automatically created if it does not exist. Each experiment creates a new subfolder containing all output responses and metrics.

In the experiment output folder, the following will be created:

- `ollama_dumps/`: raw Ollama response objects.
- `slm_inputs/`: the constructed input prompts that are sent to the SLMs.
- `slm_responses/`: the output response content produced by the SLMs, together with run ID, task category, model slug, done reason, and thinking content.
- `exp_metrics.csv`: file containing Ollama metrics and CodeCarbon metrics.
- `emissions.csv`: emissions output file generated by CodeCarbon.

The run ID is formatted as:  
`M<Model_Index><G/S>__UP<User_Prompt_Index>`.

For instance, the ID `M1G__UP001` means:

- Model #1
- General case system prompt
- User prompt #001

## LLM Judge Panel

To analyze output responses with large language models (LLMs), use the `llmjudge.py` script. It fires asynchronous requests to OpenRouter to perform LLM judging.

Before running the script, ensure the `OPENROUTER_API_KEY` has been defined in the `.env` file. Verify that the system prompt for the LLM judge is accessible at `./data/llmjudge_instructions.txt`.

In `llmjudge.py`, replace the `EXPERIMENT_ID` with the experiment ID (i.e. output folder name). List the desired LLM judge models in the `LLM_JUDGE_MODELS` list.

After running the script, the judge results will be available at `./analysis/{EXPERIMENT_ID}`. Successful outcomes will be stored in `judge_outcomes.csv` while failed attempts will be stored in `judge_failures.csv`.

## Final Data and Statistical Analysis

The final data and analysis artifacts used for the paper are available under `results/final/`:

- `experiment/`: final experiment metrics, CodeCarbon output, model inputs, and model responses.
- `judging/`: final judge outcomes and judge failure log.
- `analysis_outputs/`: tables, figures, diagnostics, and logs from the final R analysis.

The statistical analysis is implemented in `final_analysis.R`. It requires the R packages `lme4`, `lmerTest`, and `emmeans`.

From the repository root, the final analysis can be reproduced with:

```bash
Rscript final_analysis.R \
  --experiment "./results/final/experiment/exp_metrics.csv" \
  --judges "./results/final/judging/judge_outcomes.csv" \
  --require-complete-judges \
  --output-dir "./analysis_results_reproduced"
```

## Notes

User and system prompts are intentionally loaded from disk to memory just before each run. Outputs are written to disk immediately after each run and then discarded from memory. This prevents loading large chunks of data into memory during run tracking, which may affect model execution and consume extra hardware resources.

Technical or measurement failures were rerun under the same experimental conditions. Completed generations that reached the generation limit, returned truncated content, or contained no usable final response were retained as model outcomes rather than treated as technical failures.
